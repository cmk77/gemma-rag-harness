# ADR-0003: 노드별 모델 전략 — 단일 모델 다역할 vs 역할별 전용 모델

- 상태: 채택(Accepted)
- 일자: 2026-06
- 맥락 태그: 모델 서빙, 자원, 아키텍처

## 맥락

하네스에는 LLM을 호출하는 노드가 여럿 있다: ROUTER(질의 분류),
GENERATE(답변 생성), VERIFY(답변 검증), 그리고 쿼리 확장(rewrite/decompose/HyDE).
각 역할은 성격이 다르다.

- ROUTER: 짧은 분류(한 단어 출력). 빠르고 가벼우면 충분.
- GENERATE: 긴 추론·작문. 가장 높은 품질이 필요.
- VERIFY: 판정 + 진단. 중간 난도.

이때 모델을 어떻게 배치할 것인가가 문제다. 로컬 단일 GPU(RTX 6000 Ada 급)
환경에서 27B 모델을 운용한다는 제약이 핵심 변수다.

## 검토한 대안

### 대안 A — 역할별 전용 모델

- 예: ROUTER에 작은 모델(2B/9B), GENERATE에 27B, VERIFY에 중간 모델.
- 장점:
  - 각 역할에 크기·특성을 최적화 → 라우팅은 빠르게, 생성은 강력하게.
  - 작은 모델로 처리 가능한 노드의 레이턴시·비용 절감.
- 단점:
  - **VRAM 다중 점유.** 여러 모델을 동시에 메모리에 올리면 단일 GPU 예산을
    초과한다. 27B만으로도 상당한 VRAM을 쓰는데 추가 모델을 얹을 여력이 없다.
  - 모델 스왑(필요할 때 로드/언로드)은 로딩 지연을 유발해 레이턴시가 악화.
  - 모델이 여러 개면 버전·프롬프트·평가를 각각 관리 → 운영 복잡도 상승.
  - 라우팅·검증 품질이 작은 모델에서 떨어지면 파이프라인 전체 품질이 흔들림.

### 대안 B — 단일 모델 다역할 (채택)

- Gemma 4 27B 하나를 **다른 시스템 프롬프트로** ROUTER/GENERATE/VERIFY에 재사용.
- 장점:
  - **VRAM을 한 모델 분량만 쓴다.** 단일 GPU 제약에 가장 잘 맞는다.
  - 모델 스왑이 없어 노드 간 전환에 로딩 지연이 없다.
  - vLLM에 단일 모델을 띄우고 **프롬프트 캐싱**으로 공통 prefix를 재사용 →
    처리량 이득.
  - 관리 표면이 하나(한 모델, 한 엔드포인트). 프롬프트만 `prompts/*.md`로 분리.
  - 27B의 품질을 라우팅·검증에도 그대로 활용 → 약한 고리가 없다.
- 단점:
  - 라우팅처럼 가벼운 작업에도 27B를 써서 **단위 호출 비용이 작은 모델보다 큼**.
  - 한 모델에 의존 → 그 모델의 약점이 전 노드에 공통으로 나타남.

## 결정

**단일 모델 다역할을 채택한다.**

결정의 지배 변수는 **로컬 단일 GPU의 VRAM 예산**이다. 역할별 전용 모델의
이점(역할 최적화)은 매력적이지만, 그것을 누리려면 여러 모델을 동시 적재하거나
스왑해야 하고, 둘 다 이 환경에서 비용이 너무 크다. 단일 27B를 프롬프트로
다역할 운용하면 VRAM은 한 모델 분량으로 고정되고, 프롬프트 캐싱으로 처리량을
회수하며, 모든 노드가 27B 품질을 누린다.

"라우팅에 27B는 과하다"는 비용 논점은 인정하지만, 로컬 자기호스팅 환경에서는
**추가 모델의 VRAM 비용 > 큰 모델의 토큰 비용**이다. 클라우드 종량제였다면
역할별 모델이 더 경제적일 수 있어, 이 결정은 배포 환경에 종속적이다(비고 참조).

## 결과

- `models/backends.py`로 단일 모델 백엔드를 추상화(vLLM/Ollama/HF 교체 가능).
- ROUTER/GENERATE/VERIFY/쿼리확장이 같은 모델, 다른 시스템 프롬프트를 호출.
- 프롬프트는 `prompts/*.md`로 분리해 버전 관리.
- vLLM 서빙 + 프롬프트 캐싱으로 공통 prefix 재사용.

## 비고

이 결정은 **배포 환경에 종속적**이다.
- 클라우드 종량제 + 트래픽 대량 → 역할별 모델(라우팅은 소형 모델)이 비용 우위일 수 있음.
- 그 경우 백엔드 추상화 덕에 ROUTER만 다른 모델로 빼는 변경이 국소적으로 가능하다.

즉 "단일 모델"은 영구 원칙이 아니라 **현재 자원 제약에 대한 합리적 기본값**이며,
추상화 계층이 향후 전환 비용을 낮춰 둔다.
