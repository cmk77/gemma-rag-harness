# ADR-0004: 검색 폭(BASE_K) 상향 및 VERIFY 프롬프트 강화

- **상태**: 채택됨 (Accepted)
- **일자**: 2026-07-03
- **결정자**: 김창모 (Mozi)
- **관련 컴포넌트**: `harness/adaptive_retrieve.py`, `prompts/verify.md`, `harness/graph.py`

---

## 1. 배경 (Context)

`gemma-rag-harness`는 기술문서 코퍼스를 대상으로 하는 자가검증 RAG 에이전트다.
LangGraph 6노드 파이프라인(ROUTER → RETRIEVE → GENERATE → VERIFY + 재검색 루프)에
Elasticsearch 하이브리드 검색(BM25 + bge-m3 kNN, RRF 융합)을 결합했다.

운영 중 다음 실패 케이스가 발견됐다.

> **질문**: "API 게이트웨이 제품이 받은 인증은 무엇인가요?"
> **정답**: 품질인증 1등급 (공인 인증, certification)
> **하네스 답변**: "Basic·API Key·JWT·OAuth2 인증" (제품이 지원하는 사용자 인증, authentication)

즉 한국어 "인증"의 중의성(**certification** 공인 인증 ↔ **authentication** 사용자 인증)
때문에, 질문이 요구한 것과 다른 범주의 문서를 근거로 답하는 오답이 발생했다.

### 진단으로 확정된 원인 사슬

1. **정답 문서는 색인에 정상 존재한다.** ES `text` 필드로 "품질인증"을 검색하면
   25건이 매칭되고 최상위 점수는 7.4다. (초기에 `content` 필드로 검색해 0건이
   나온 것은 필드명 오류였고, 진단 자체가 무효였다.)
2. **BM25 단독은 정답을 1위로 찾는다.** 순수 키워드 검색에서 품질인증(certification)
   문서가 최상위로 나온다.
3. **하이브리드 검색의 벡터 성분이 오답을 유발한다.** bge-m3가 "인증"을
   authentication 의미 쪽으로 임베딩해, authentication 문서와의 벡터 유사도가
   높게 나온다. RRF 융합 결과 authentication 문서가 top-5를 차지하고,
   정답인 certification 문서가 컨텍스트에서 밀려난다.
4. **VERIFY 판정이 불안정하다.** 동일한 authentication top-5에 대해,
   질문 표현이 "받은"이면 VERIFY가 `ok`(통과)를, "취득했나요"이면
   `insufficient`(재검색)를 준다. 후자는 재검색으로 문서가 늘어 우연히 정답이
   되지만, 전자는 오답이 그대로 통과된다. 즉 **정답 여부가 질문 표현과 LLM
   샘플링 무작위성에 좌우된다.**

문제는 두 층위에 걸쳐 있다: (A) 첫 검색이 정답 문서를 컨텍스트에 못 넣는 것,
(B) VERIFY가 질문-답변 주제 불일치를 일관되게 걸러내지 못하는 것.

---

## 2. 결정 (Decision)

두 층위를 각각 겨냥해 아래 두 가지를 함께 적용한다.

### 결정 1 — `BASE_K`를 5에서 10으로 상향

`harness/adaptive_retrieve.py`의 첫 검색 문서 수를 5 → 10으로 올린다.

재검색으로 문서가 9개까지 늘면 정답 문서가 컨텍스트에 들어오는 것이 이미
관측됐다. 따라서 **첫 검색부터 top-10을 가져오면**, 벡터 성분이 authentication을
상위로 올리더라도 certification 문서가 top-10 안에 포함되어, 재검색 발동 여부와
무관하게 정답 근거가 컨텍스트에 존재하게 된다.

### 결정 2 — VERIFY 프롬프트에 질문-답변 주제 정합성 검사 추가

기존 VERIFY는 "답변이 근거에 충실한가(faithfulness)"만 검사했다. 여기에
**"답변이 질문이 요구한 대상·범주에 실제로 부합하는가(answer-question topical
alignment)"** 판정을 추가한다. 불일치 시 `insufficient`로 판정해 재검색을
트리거한다.

예: 질문이 "받은 인증"(certification)인데 답변이 authentication 기능이면,
근거에는 충실하더라도 질문 범주와 어긋나므로 `insufficient`.

---

## 3. 근거 (Rationale)

- **이중 안전장치**: 결정 1이 첫 검색에서 정답을 잡고(1차 방어), 혹시 놓쳐도
  결정 2가 재검색을 강제한다(2차 방어). 한쪽만으로는 불안정성이 남는다.
- **근본 원인 대응**: 오답의 진짜 원인은 "정답이 컨텍스트에 없어서"이므로,
  검색 폭 확대가 가장 직접적이다. VERIFY 강화만으로는 재검색이 정답을
  보장하지 못한다(재검색해도 여전히 못 찾을 수 있음).
- **저비용**: 두 변경 모두 코드 몇 줄과 프롬프트 수정으로, 인덱스 재구축이나
  임베딩 모델 교체 없이 적용 가능하다.

## 4. 검토한 대안 (Alternatives Considered)

| 대안 | 내용 | 채택하지 않은 이유 |
|---|---|---|
| **A. BM25 가중치 상향** | RRF 융합에서 BM25 비중을 높여 벡터 오류 완화 | 다른 질의(의미 검색이 유리한 경우)의 재현율을 떨어뜨림. 이 케이스만 위해 전역 파라미터를 편향시키는 것은 부작용이 큼 |
| **B. 임베딩 모델 교체** | bge-m3 → 한국어 특화/최신 임베딩 | 비용·시간 대비 불확실. "인증" 중의성은 모델을 바꿔도 남을 수 있는 언어적 문제 |
| **C. 질의 확장/재작성만** | ROUTER에서 "인증"을 "인증 등급/공인 인증/인증 방식"으로 확장 | 유효하나 단독으론 첫 검색 폭 부족 문제를 못 풀음. 결정 1·2의 **보완책**으로 후속 검토(ADR-0002 후보) |
| **D. 청킹 재설계** | certification과 authentication을 다른 청크로 명확 분리 | 재색인 필요, 범위 큼. 현 오답은 청킹보다 검색 랭킹 문제이므로 우선순위 낮음 |
| **E. 아무것도 안 함** | 재검색이 가끔 정답을 냄 | 정답이 표현·샘플링 운에 좌우됨. 포트폴리오·운영 관점에서 허용 불가 |

결정 1+2는 A~D 대비 **부작용이 국소적이면서 근본 원인(컨텍스트 부재 + 검증
느슨함)을 직접 겨냥**한다는 점에서 선택됐다. C는 향후 보완책으로 남겨둔다.

## 5. 결과 (Consequences)

### 긍정적

- 미묘하게 다른 두 질문에 각각 정확한 답이 나온다.
  - "받은 인증" → 품질인증 1등급 (certification)
  - "지원하는 인증" → Basic·API Key·JWT·OAuth2 (authentication)
- 두 답 모두 **재검색 0회로 검증 통과**한다. 이는 불안정성이 아니라, 첫
  검색부터 올바른 근거를 확보해 재검색이 불필요해진 상태다.
- 정답이 질문 표현·샘플링 무작위성에 덜 좌우되어 **재현성이 향상**된다.

### 부정적 / 트레이드오프

- **컨텍스트 길이 증가**: top-5 → top-10으로 GENERATE 입력 토큰이 늘어
  레이턴시·토큰 비용이 소폭 증가한다. (E4B+MTP 기준 체감 영향은 측정 대상.)
- **노이즈 유입 가능성**: 관련성 낮은 문서가 컨텍스트에 더 들어올 수 있어,
  VERIFY와 GENERATE의 노이즈 내성이 함께 요구된다.

### 검증 방법 (측정으로 확인)

1. **골든셋 재평가** (`--goldenset`으로 지정한 골든셋):
   직전 baseline 리포트 대비 correctness 상승 확인.
2. **일관성 검증** (`eval/consistency_pairs_sample.jsonl` + `run_consistency.py`):
   - discriminative 페어(중의성 구분)가 서로 다른 정답을 내는지
   - invariant 페어(표현 변주)가 같은 정답으로 수렴하는지
   - 같은 질문 N회 반복 시 route 안정성
3. **레이턴시 벤치**: top-10 전환에 따른 p50/p95 변화 계측 → 트레이드오프 정량화.

> 재평가에서 correctness가 baseline 이하이거나, invariant 페어가 여전히
> 갈리면 이 결정을 재검토하고 대안 C(질의 확장) 또는 A(BM25 가중치)를
> 추가 적용한다.
